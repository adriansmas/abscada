# Revisión transversal — 4 de octubre de 2026

Se revisaron modelo y validación del proyecto, persistencia y Git, adquisición y adaptadores S7/Modbus, alarmas, archivo diario y consultas históricas, scripts, edición gráfica, ventanas y controles de runtime. La revisión combina lectura de código, inyección de fallos y pruebas de integración y de interfaz. No constituye una garantía de ausencia de errores ni una validación industrial.

## Fallos corregidos

| Área | Problema y corrección |
| --- | --- |
| Arranque | Un fallo al iniciar scripts podía dejar adquisición y archivo abiertos. El arranque revierte los servicios iniciados y libera el bloqueo. La ventana fallida también se cierra. |
| Exclusión | La exclusividad dependía del archivo SQLite. Ahora cada proyecto admite un único runtime aunque no tenga registros configurados. |
| Parada | Las variables PLC podían conservar calidad buena al detener la adquisición. Pasan a inciertas y se rechazan escrituras a conexiones detenidas. |
| Scripts | Tareas y eventos podían intercalarse con la inicialización. Los scripts de inicio se completan en orden antes de atender los demás eventos. |
| Memoria | La salida de Python se truncaba después de acumularla. Ahora la captura mantiene una cola de texto limitada mientras se escribe. El historial del editor agrupa pulsaciones; el panel de diagnóstico limita sus bloques. |
| Alarmas | El ACK esperaba a SQLite en el hilo gráfico. Ahora se solicita en segundo plano. Los errores del escritor detienen el servicio en vez de continuar tras una operación fallida. |
| Alarmas retiradas | Una definición eliminada o deshabilitada podía dejar una instancia activa indefinidamente. Se registra su deshabilitación y se conserva el reconocimiento pendiente. |
| Históricos | Una consulta limitada podía terminar antes de consultar archivos con datos más antiguos. Se combinan los resultados de los archivos antes de aplicar el límite cronológico. |
| Botones | Soltar el ratón fuera del botón ejecutaba la orden. La activación requiere pulsación izquierda y liberación dentro. |
| Validación | Se comprueban acciones, tipos y nombres portables. La conversión de enteros evita pasar por float y perder precisión de enteros de 64 bits. Asociar una variable no booleana a un botón nuevo selecciona la acción de asignación. |
| Guardado | La restauración se hacía escribiendo directamente sobre los destinos. Ahora utiliza copias previas y reemplazos; si la restauración también falla, conserva las copias restantes en una carpeta de recuperación indicada en el error. |
| Git | Nombres de assets con caracteres de patrones, como corchetes, podían interpretarse como expresiones. Se utilizan rutas literales. |
| Ventanas | Los diálogos modales con padre podían acumular sus widgets después de cerrarse. Se liberan una vez leído el resultado. |
| Cierre SQLite | Se garantiza liberar el bloqueo y resolver solicitudes pendientes aunque falle el cierre del repositorio; las órdenes nuevas se rechazan durante la parada. |

Las regresiones específicas están en `tests/test_audit.py`. La suite existente cubre además edición con ratón, layouts, emergentes, faceplates, listas de textos, formularios, guardado, versiones, scripts, alarmas y adquisición TCP. El resultado agregado se documenta en `VALIDATION.md`.

## Límites pendientes de validación

- Las pruebas de esta revisión se ejecutan en Windows; Qt usa la plataforma offscreen. Falta repetirlas en Linux y verificar los instaladores.
- La comunicación se prueba con servidores TCP de desarrollo, no con un PLC físico ni todas las variantes de CPU.
- Faltan ensayos sostenidos de carga, volumen histórico y desconexión/reconexión con hardware real antes de fijar capacidades soportadas.
- El guardado con recuperación no es una transacción atómica frente a cortes de alimentación entre archivos.
- Los scripts son Python de confianza con los permisos del usuario. El proceso separado y su timeout no constituyen una sandbox.
- Un ACK ya iniciado en SQLite no se puede cancelar de forma segura porque venza la espera del solicitante. Las solicitudes todavía en cola sí se cancelan al vencer el plazo; debe consultarse el estado persistido ante un error de espera.

La arquitectura mantiene separación entre proyecto, adquisición, archivo, scripts y visualización. La revisión mejora fallos concretos; no sustituye las pruebas de aceptación de una instalación real.
